# 2.5 Scripts：可执行自动化入口（总结与可复用技巧）

## 一、这四个脚本分别是什么

- `copilotPrepare.ps1`：任务文档生命周期管理器（初始化、覆盖、备份、清理）。
- `copilotBuild.ps1`：统一构建门面（自动定位 solution + 统一日志 + 退出码透传）。
- `copilotExecute.ps1`：统一运行门面（自动选择最新 exe + 自动注入调试参数 + 统一日志）。
- `copilotShared.ps1`：公共能力层（路径发现、产物选择、参数提取）。

它们组合起来形成一个典型的自动化链路：

1. **Prepare** 先把任务上下文和文档状态归一；
2. **Build** 在统一环境和参数下编译；
3. **Execute** 在统一入口和日志策略下运行；
4. **Shared** 提供可复用基础设施，避免重复逻辑散落在多个脚本中。

---

## 二、内容结构上的共同特点

1. **入口明确**：每个脚本只负责一个“规范动作”。
2. **失败前置**：参数/环境变量先校验，不满足就快速失败。
3. **日志原子化**：先写 `*.unfinished`，成功后再改名为正式日志，避免半截日志污染。
4. **退出码透明**：最终返回真实退出码，便于 CI 或上层脚本判断状态。
5. **自动发现而非硬编码**：如向上查找 solution、按修改时间挑选产物。
6. **共享抽象下沉**：公共逻辑统一放 `copilotShared.ps1`，降低维护成本。

## 三、可以学习到的技巧

### 技巧 1：参数互斥与模式切换
用开关参数（如 `-Backup` / `-Earliest`）表达运行模式，同时做互斥校验，防止脚本进入不确定状态。

### 技巧 2：稳定日志写入策略
`output -> *.unfinished -> rename` 是非常实用的工程技巧，能避免中断时留下“看似完整、实则损坏”的日志。

### 技巧 3：环境依赖显式化
通过环境变量（`VLPP_VSDEVCMD_PATH`, `CDBPATH`）管理外部依赖，并在错误信息里给出可执行示例，显著降低新环境配置成本。

### 技巧 4：目录向上搜索
`GetSolutionDir` 的“从当前目录向上查找”模式可迁移到很多工程（monorepo、子模块工作流），使脚本对调用位置更鲁棒。

### 技巧 5：按“最新修改时间”选产物
在多配置/多平台产物并存时，选择最新构建产物能减少人工指定路径错误。

### 技巧 6：把 IDE 配置用于自动执行
从 `.vcxproj.user` 自动读取 `LocalDebuggerCommandArguments`，减少“能在 IDE 跑、命令行跑不起来”的配置漂移。

### 技巧 7：门面脚本 + 共享库分层
把“任务编排”与“底层能力”分离（Build/Execute vs Shared），使脚本演进更可控，也更容易测试和替换。

---

## 四、建议如何在其它项目复用

1. 先做 `shared` 层：路径发现、日志、错误模型。
2. 再做 `prepare/build/execute` 三个门面命令。
3. 每个门面都统一输出日志和退出码。
4. 对外部工具路径统一用环境变量，错误信息给可复制示例。
5. 针对团队常见误操作（参数后缀、目录位置、配置错配）做前置校验。

这样可以把“人依赖经验”的流程，逐步变成“脚本保证一致性”的流程。
